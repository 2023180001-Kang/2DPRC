# 2DPRC

Python과 pico2d로 구현한 2D 액션 게임의 기본 이동 프로토타입입니다. 제공된 골목 배경에서 새 캐릭터 시트의 대기, 걷기, 달리기, 점프를 확인할 수 있습니다. Java 및 JavaScript는 사용하지 않습니다.

## 빠른 실행

현재 작업 공간에는 `.venv`와 의존성이 준비되어 있습니다. 프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe main.py
```

새 환경에서는 먼저 Python 3을 설치한 뒤 다음 명령으로 준비합니다. 검증한 환경은 Windows 및 Python 3.13.15입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

가상환경 활성화나 PowerShell 실행 정책 변경은 필요하지 않습니다. 창이 표시되는 데스크톱 환경이 필요하며, 처음 의존성을 설치할 때는 패키지 다운로드를 위한 네트워크 연결이 필요합니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 지상에서 입력 없음 | 마지막으로 바라본 방향의 IDLE |
| 왼쪽 / 오른쪽 방향키 | 해당 방향으로 걷기 |
| R을 누른 채 왼쪽 / 오른쪽 방향키 | 해당 방향으로 달리기 |
| 이동 중 R 해제 | 걷기로 전환 |
| 방향키 해제 | 즉시 수평 정지 |
| R 단독, 좌우 동시 입력 | 수평 정지 |
| 지상에서 스페이스바 새로 누르기 | 한 번 점프 |
| 창 닫기 | 게임 종료 |

좌우 동시 입력에서 한쪽을 놓으면 남은 방향키와 R 상태에 따라 다시 이동합니다. R과 방향키의 누르는 순서는 관계없습니다. 위아래 방향키와 공격은 지원하지 않습니다.

점프 중에도 좌우 및 R 조작이 가능하며, 방향키를 놓아도 중력에 따라 하강합니다. 공중 재점프나 점프 예약은 없고, 스페이스바를 계속 누른 채 착지해도 자동으로 다시 뛰지 않습니다. 다음 점프는 착지 후 스페이스바를 놓았다가 다시 누릅니다. 키를 누르는 길이는 점프 높이에 영향을 주지 않습니다.

창 포커스를 잃으면 누른 키와 미처리 점프 요청을 초기화하므로, 돌아온 뒤에는 키를 다시 눌러야 합니다. 이미 시작한 점프는 정상적으로 착지합니다.

## 적용 설정

| 항목 | 값 |
| --- | --- |
| 화면 | 1280 x 720, 고정 카메라, 비율을 유지하며 배경으로 화면 전체 채우기 |
| 배경 | `newfirststage.png` |
| 걷기 / 달리기 | 180 / 320 화면 픽셀/초 |
| 상태별 애니메이션 | IDLE 6 FPS, WALK 8 FPS, RUN 12 FPS, JUMP 10 FPS |
| 캐릭터 시트 | `MainCharacter_pico2d_2048x1024.png`, 256 x 256 프레임, 8열 x 4행 |
| 표시 배율 / 지상 발 높이 | 0.6배 / 화면 아래에서 140픽셀, 새 배경의 보도 위 |
| 점프 | 초기 수직 속도 480 px/s, 중력 1200 px/s², 정점 96픽셀, 체공 약 0.8초 |
| 초기 위치 / 시선 | 화면 수평 중앙 / 오른쪽 |
| 화면 경계 | 전체 프레임이 화면에 머물도록 제한, 경계에서도 상태 애니메이션 유지 |
| 렌더링 목표 | 최대 60 FPS, 환경에 따라 실제 값은 낮아질 수 있음 |

설정은 `settings.py`에서 조정합니다. 화면 크기, 캐릭터 배율, 바닥 높이를 변경하면 배경과 캐릭터 배치를 다시 확인해야 합니다.

네 번째 행의 점프 프레임은 실제 점프 진행 시간에 맞춰 한 번 재생하고 마지막 프레임을 유지합니다. 착지하면 현재 방향키와 R 입력에 맞는 지상 상태로 전환합니다.

배경은 중앙 기준으로 화면을 덮도록 확대·축소하며 남는 가장자리는 잘라냅니다. 픽셀 크기를 올림 처리하여 미세한 비율 차이로 빈 줄이 생기는 것을 방지합니다.

## 개발 및 검증

이미지 생성 도구와 테스트에는 Pillow가 추가로 필요합니다. 게임 실행 자체는 `requirements.txt`만으로 가능합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe main.py --frames 180
.\.venv\Scripts\python.exe -m tools.verify_runtime
```

- 자동 테스트는 75개이며 기존 이동, 점프 궤적과 재점프 방지, SDL 입력·포커스, 32프레임 정렬·클리핑, 리소스 및 자원 정리를 검증합니다.
- `--frames N`은 양의 정수 N프레임 후 종료하고 실제 실행 시간 및 평균 FPS를 출력합니다.
- `tools.verify_runtime`은 실제 창에서 기존 이동 482프레임과 점프 191프레임을 실행하고 화면 14개 및 측정 결과를 `artifacts/`에 생성합니다. 실행 중에는 게임 창을 조작하지 마세요.
- 실제 창 입력 검증은 물리 키보드의 사람 조작이 아닌 이벤트 큐 기반 검증입니다. 상세 결과와 남은 확인 사항은 `VERIFICATION.md`를 참조합니다.

## 게임 리소스

현재 배경은 사용자가 추가한 `newfirststage.png`입니다. 기존 `firststage.png`는 보존하지만 게임 실행 시에는 사용하지 않습니다.

현재 캐릭터 원본은 `MainCharacter_pico2d_2048x1024.png`이며, IDLE/WALK/RUN/JUMP를 위에서부터 1~4행에 매핑합니다. 실행 시에는 새 원본을 정렬한 `assets/character.png`를 사용합니다. 생성된 파일은 저장소에 포함되어 있어 실행 전에 다시 생성할 필요는 없습니다. 기존 `MainCharacter.png`는 보존만 하며 게임과 생성 도구에서 읽지 않습니다.

다음 명령은 원본 캐릭터 시트에서 파생 파일을 재생성하고 컬러 배경의 검토용 미리보기를 만듭니다. 모듈 실행 방식(`-m`)을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m tools.prepare_character --preview
```

새 시트는 이미 투명 배경이므로 별도의 색상 기반 배경 제거는 하지 않습니다. 생성 도구는 알파 128 미만의 미세한 잔여 픽셀을 정리하고, 32개 프레임을 수평 중앙 및 동일한 발 기준점에 정렬합니다. 원본 PNG는 수정하지 않습니다. 점프 높이는 시트 여백이 아닌 게임 물리 좌표로 계산합니다.

## 파일 구성

| 경로 | 역할 |
| --- | --- |
| `main.py` | pico2d 창, 메인 루프, 실행 옵션, 자원 수명 관리 |
| `game.py` | 창 없이 검증 가능한 입력, 이동, 점프 물리 및 상태 |
| `events.py` | pico2d가 사용하는 SDL의 키, 포커스, 종료 이벤트 처리 |
| `rendering.py` | 배경 및 프레임 렌더링 |
| `resources.py` | 소스 위치 기준 이미지 경로, 오류 안내, 텍스처 해제 |
| `settings.py` | 크기, 속도, 애니메이션 및 배치 설정 |
| `tools/` | 파생 이미지 생성과 실제 창 검증 도구 |
| `tests/` | Python unittest 테스트 |
| `DEVELOPMENT.md` | 개발 기준과 20단계 진행 기록 |
| `VERIFICATION.md` | 측정 결과, 인수 기준별 검증, 남은 제약 |
| `PRD.md` | 개발 요구 사항 |

## 제약 및 문제 해결

- 이번 버전은 고정 화면의 이동·점프 프로토타입입니다. 실제 횡스크롤 카메라, 전투, 공중 재점프, 플랫폼 및 장애물 충돌은 없습니다.
- 배경 사물은 그림이며 캐릭터 이동을 막지 않습니다.
- `Game error`에 파일 경로가 표시되면 해당 이미지가 있는지 확인합니다. 파생 캐릭터 파일이 없으면 위 재생성 명령으로 복구할 수 있습니다.
- 창 생성 또는 SDL 로딩이 실패하면 `requirements.txt`를 가상환경에 설치했는지와 데스크톱 그래픽 환경을 확인합니다. 다른 운영체제의 구동은 검증하지 않았습니다.
- pico2d 1.5.1의 이벤트 및 텍스처 수명 동작에 맞춰 구현했으므로, 의존성 버전을 변경하면 테스트와 실제 창 검증을 다시 실행해야 합니다.
