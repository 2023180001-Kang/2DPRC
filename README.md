# 2DPRC

Python과 pico2d로 구현한 2D 액션 게임 프로토타입입니다. 화살표를 통한 두 맵 왕복 이동, 맵별 랜덤 아이템과 상태 보존, Shift 달리기, 더블 점프, HP 바와 F키 무기 획득·교체·지상/공중 버리기 및 근접 F 안내를 확인할 수 있습니다. 무기를 주우면 새 5상태 시트의 오른손에 위를 향하도록 장착하고, A키로 맨손·무기 공격 동작을 재생합니다. 공중에 버린 무기는 중력에 따라 떨어져 보도에 착지합니다. Java 및 JavaScript는 사용하지 않습니다.

각 맵에는 적 1명이 랜덤 배치됩니다. 적은 플레이어를 인식하면 지상에서 따라오고 가까이서 멈춥니다. 가까이에서 적을 바라보며 **A를 한 번 눌러 쓰러뜨리고, 완전히 쓰러진 뒤 나타나는 오른쪽 화살표로 진행**합니다.

적의 몸통 높이에서 닿으면 멈추고 IDLE을 표시하며, 충분히 높이 점프하면 적 위로 넘어갈 수 있습니다. 처치한 뒤에도 **시체가 낮은 장애물로 남으므로 점프로 올라서거나 넘어가야** 합니다. 시체 위에 착지해 서 있거나 다시 점프할 수 있고, 가장자리에서 걸어 나가면 보도로 떨어집니다.

## 빠른 실행

현재 작업 공간에는 `.venv`와 의존성이 준비되어 있습니다. 프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe main.py
```

새 환경에서는 먼저 Python 3을 설치한 뒤 다음 명령으로 준비합니다. 검증한 환경은 Windows 및 Python 3.13.15입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

가상환경 활성화나 PowerShell 실행 정책 변경은 필요하지 않습니다. 창이 표시되는 데스크톱 환경이 필요하며, 처음 의존성을 설치할 때는 패키지 다운로드를 위한 네트워크 연결이 필요합니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 지상에서 입력 없음 | 마지막으로 바라본 방향의 IDLE |
| 왼쪽 / 오른쪽 방향키 | 해당 방향으로 걷기 |
| 왼쪽 또는 오른쪽 Shift + 좌우 방향키 | 해당 방향으로 달리기 |
| 이동 중 마지막 Shift 해제 | 걷기로 전환 |
| 방향키 해제 | 즉시 수평 정지 |
| Shift 단독, 좌우 동시 입력 | 수평 정지 |
| 지상에서 스페이스바 새로 누르기 | 한 번 점프 |
| 첫 점프 후 공중에서 스페이스바를 놓고 다시 누르기 | 추가 1회 점프, 한 번의 체공 중 최대 2회 |
| 지상에서 무기 근처로 접근 후 F 새로 누르기 | 가장 가까운 무기 획득, 이미 무기가 있으면 교체 |
| 지상에서 주울 수 있는 무기가 없을 때 F 새로 누르기 | 소지 무기를 발밑에 버리기, 맨손이면 동작 없음 |
| 점프 중 F 새로 누르기 | 소지 무기 버리기, 무기는 현재 위치에서 낙하 후 착지 |
| A 새로 누르기 | 맨손·무기 공격 1회, 전방 가까운 적은 한 번에 쓰러짐 시작 |
| 적이 완전히 쓰러진 뒤 첫 맵 오른쪽 화살표에 접근 | 별도 키 없이 두 번째 맵으로 이동 |
| 두 번째 맵 왼쪽 화살표에 접근 | 첫 번째 맵으로 돌아가기 |
| 두 번째 맵 오른쪽 화살표에 접근 | 현재는 동작 없음, 두 번째 맵 유지 |
| 창 닫기 | 게임 종료 |

좌우 동시 입력에서 한쪽을 놓으면 남은 방향키와 Shift 상태에 따라 다시 이동합니다. Shift와 방향키의 누르는 순서는 관계없습니다. 두 Shift를 함께 눌렀다가 하나만 놓아도 달리기가 유지됩니다. R은 더 이상 달리기 키가 아니며, R+방향키는 걷기입니다. 위아래 방향키는 사용하지 않습니다.

A를 새로 누르면 맨손·무기 소지 중 모두 8프레임의 공격 동작을 16 FPS로 0.5초 동안 재생합니다. 이동·달리기·더블 점프 중에도 공격할 수 있습니다. **공격이 재생되는 동안 전방 100픽셀 이내·발 높이 차이 80픽셀 이내에 들어온 적은 즉시 쓰러지기 시작합니다.** 달리면서 범위 밖에서 공격을 시작해도 동작이 끝나기 전에 도달하면 명중합니다. 이동을 최대 1/120초로 나누어 판정하며 한 공격은 한 번만 명중합니다. A를 유지하거나 공격 중 다시 눌러도 연속/예약 공격은 발생하지 않고, 공격 종료 후에는 접근해도 명중하지 않습니다. Z는 공격 입력으로 사용하지 않습니다. F로 무기를 교체하거나 버리면 현재 공격을 종료합니다. 맵 전환 중에는 공격을 이어갑니다.

첫 스페이스바 입력은 지상 점프, 공중의 두 번째 새 입력은 더블 점프입니다. 상승·하강 중 모두 가능하고, 두 번째 도약은 현재 높이에서 수직 속도를 초기 점프 속도로 다시 설정합니다. 기존 속도에 더하지 않습니다. 세 번째 입력은 착지 전까지 무시하고, 착지하면 사용 횟수를 0으로 초기화합니다.

점프 중에도 좌우 및 Shift 조작이 가능하며, 방향키를 놓아도 중력에 따라 하강합니다. 스페이스바를 길게 누르거나 반복 이벤트가 발생해도 자동으로 추가 도약하지 않으며, 사용 횟수를 다 쓴 입력은 예약하지 않습니다. 착지 후에도 새로 눌러야 다음 점프를 시작합니다. 키를 누르는 길이는 도약 속도에 영향을 주지 않습니다.

창 포커스를 잃으면 누른 키와 미처리 점프·F·A 요청을 초기화하므로, 돌아온 뒤에는 키를 다시 눌러야 합니다. 이미 시작한 점프·공격·소지 무기·사용한 점프 횟수는 유지하며, 포커스 전환으로 점프 횟수가 회복되지 않습니다.

F로 줍는 범위는 플레이어 발 좌표에서 무기 중심까지 56픽셀입니다. 범위 안에 여러 개가 있으면 가장 가까운 한 개만 선택하며, 길게 누르고 있어도 자동 반복하지 않습니다. 획득·교체는 지상에서 실행하고, 공중에서는 소지 무기 버리기만 실행합니다. 실패한 입력을 착지·접근 후 자동 실행하지 않습니다.

무기는 한 번에 하나만 들며 처음에는 맨손입니다. 주운 무기는 바닥에서 없어지고 캐릭터 손 근처에 표시됩니다. 이미 무기를 들고 있다면 새 무기로 교체하면서 이전 무기는 발밑에 내려놓습니다. 근처에 주울 무기가 없는 지상에서 F를 누르면 소지 무기를 발밑에 버리고 맨손이 됩니다. 버린 직후에는 자동으로 다시 줍지 않으며, F를 놓았다가 누르면 재획득합니다. F 입력이 없으면 이동·달리기·점프·착지 중에도 소지를 유지합니다.

점프의 상승·정점·하강 및 더블 점프 중에도 F를 새로 누르면 즉시 맨손이 됩니다. 버린 무기는 현재 캐릭터 x·발 높이+32픽셀에서 시작해 중력으로 아래로 떨어집니다. 캐릭터가 좌우로 이동해도 무기는 버린 x에서 낙하하고, 보도 높이 140픽셀에 착지하면 정지합니다. 낙하 중에는 줍기와 F 안내 대상에서 제외하며, 착지 후 가까이 다가가 F를 새로 누르면 다시 주울 수 있습니다. F 유지·반복으로 복제하거나 자동 재획득하지 않습니다.

획득 가능한 가까운 무기 위에는 작은 `F` 글자만 나타납니다. 안내가 가리키는 무기가 실제 F 입력의 획득·교체 대상이며, 이미 무기를 소지해도 표시됩니다. 멀어지거나 점프하면 숨기고, 교체·버리기로 발밑에 놓인 무기에도 같은 안내를 표시합니다. 상자 배경과 테두리는 표시하지 않으며 기존 글자의 위치·크기·색상을 유지합니다.

## 화살표와 맵 왕복 이동

게임은 `newfirststage.png`의 첫 맵에서 시작하며 적이 살아 있거나 쓰러지는 중에는 오른쪽 화살표가 나타나지 않고 이동도 차단됩니다. 적이 8프레임·1초의 쓰러짐 동작을 끝내면 오른쪽 화살표가 나타납니다. 지상·공중에서 고정 기준 x±30픽셀에 접근하면 `firstSecondmap.png`의 두 번째 맵으로 이동합니다. 두 번째 맵에는 새 적 1명이 있으며 왼쪽 복귀 화살표는 적 상태와 무관하게 항상 작동합니다. 오른쪽은 해당 맵 적의 처치 완료 후에만 표시합니다.

적은 수평 거리 **420픽셀 이내에서 플레이어를 인식**하고 초당 **120픽셀**로 따라옵니다. 한 번 인식하면 560픽셀까지 추적을 유지하고, 이를 벗어나면 멈췄다가 420픽셀 안에서 재인식합니다. 점프한 플레이어는 지상에서 따라가며 반대편으로 넘어가면 시선을 바꿉니다.

**거리 90픽셀·발 높이 차이 80픽셀 이내에서는 적이 공격합니다.** 시트의 공격 8프레임을 12 FPS로 재생하고 약 0.333초의 타격 시점에 전방 100픽셀·높이 차이 80픽셀 이내면 HP가 10 줄어듭니다. 준비 동작 중 뒤로 물러나거나 점프해 회피할 수 있고, A 반격으로 적을 쓰러뜨리면 공격이 취소됩니다. 공격 후 0.6초 동안 재공격을 기다리며, 이때는 추적하거나 중심 거리 64픽셀 앞에서 대기합니다. 단순 몸통 접촉은 피해를 주지 않습니다.

추적 중에도 A 한 번으로 쓰러뜨릴 수 있으며, 피격 즉시 이동을 멈추고 쓰러진 후에는 마지막 누운 모습을 유지합니다. 맵별 적은 재방문 때 추가 생성되지 않습니다. 다른 맵으로 나가면 적의 위치·시선·인식·애니메이션을 보존하고 돌아온 뒤 다시 추적 판단을 시작합니다.

다음 맵은 왼쪽 x=128, 이전 맵은 오른쪽 x=1152에서 시작합니다. 도착 위치는 고정 화살표 범위 밖입니다. **방향키·Shift를 누른 채 전환하면 키를 다시 누르지 않아도 이동이 이어집니다.** 지상에서는 y=140에 도착하며 현재 입력에 맞는 걷기·달리기를 적용합니다. 점프 중이면 높이·수직 속도·점프 횟수·JUMP 애니메이션·시선을 그대로 유지하여 새 맵에서 같은 점프를 이어갑니다. 체력·소지 무기를 유지하고 스테이지마다 첫 방문에만 아이템을 3~5개 생성합니다. 재방문하면 획득·버리기 상태를 그대로 복원합니다.

첫 점프 중 이동했다면 새 맵에서도 스페이스바를 놓았다가 다시 눌러 추가 1회 도약할 수 있습니다. 더블 점프를 이미 사용했다면 스테이지를 바꿔도 세 번째 도약은 불가능합니다. 도착한 맵에 착지하면 횟수가 0으로 돌아가고 다시 새 입력으로 점프할 수 있습니다.

화살표는 기준 위치에서 **좌우 6픽셀씩, 1.2초 주기**로 부드럽게 왕복합니다. 크기와 세로 위치는 고정이며 이동 판정은 시각적 움직임과 무관하게 기준 중심을 사용합니다. 스테이지 전환 후에도 애니메이션 위상이 이어집니다. 전환 시 눌린 키 상태는 보존하되 미처리 점프·F·A 요청만 정리하여, Space나 F·A를 계속 누르고 있어도 새 맵에서 자동으로 다시 실행되지 않습니다.

현재 스테이지는 두 개입니다. **두 번째 맵의 오른쪽 화살표는 표시만 하며 접근해도 이동·재스폰·상태 초기화를 하지 않습니다.** 기존 포털 표시는 화살표로 교체했습니다.

설정은 `settings.py`에서 조정합니다. 화면 크기, 캐릭터 배율, 바닥 높이를 변경하면 배경과 캐릭터 배치를 다시 확인해야 합니다.

단일 점프의 높이와 속도는 이전 버전 그대로입니다. 더블 점프의 전체 높이·체공 시간은 두 번째 입력 시점에 따라 달라집니다. 맨손은 네 번째 행, 무기 소지는 다섯 번째 행의 8프레임을 각 도약에서 재사용하며, 두 번째 도약 때 애니메이션을 다시 시작합니다. 좌우/Shift 변경이나 세 번째 입력으로는 프레임을 초기화하지 않습니다. 공격 중에는 공격 표시를 우선하며 점프 궤적은 계속 갱신합니다. 착지하면 현재 입력에 맞는 지상 상태로 돌아옵니다.

체력 HUD는 `HoodMan_HP바_투명배경_pico2d.png`를 사용하며 화면 왼쪽 상단을 기준으로 표시합니다. 초기·최대 HP는 **100**, 적 근접 피해는 **10**으로 세 번 맞아도 **HP 70**이 남습니다. 파란 게이지는 HP/100 비율로 줄어듭니다. 실제 피격 때 카메라는 0.30초, HP바는 더 작게 0.24초 흔들린 뒤 원위치로 돌아오며 초상화·테두리·게이지가 함께 움직입니다. 효과는 표시 좌표에만 적용하여 충돌이나 공격 판정에 영향을 주지 않습니다. 피격 후 0.8초 동안 추가 피해를 막으며 맵을 바꿔도 HP·무적·남은 피격 효과가 이어집니다. 수치는 `settings.py`의 `MAX_HEALTH`, `ENEMY_ATTACK_DAMAGE`, `CAMERA_SHAKE_*`, `HEALTH_SHAKE_*`에서 조정합니다.

**HP 0의 마지막 타격이 정면에서 오면 뒤로 쓰러지고, 후방에서 오면 앞으로 엎드립니다.** 새 시트 마지막 행의 두 구간을 따로 재생하며 좌우 시선에 맞춰 반전합니다. 사망 중에는 이동·점프·F·A·맵 이동을 할 수 없고 무기 합성은 숨깁니다. 공중에서 사망하면 보도로 떨어져 각 동작의 마지막 자세를 유지합니다. 게임 오버 화면·재시작·회복 기능은 아직 없습니다.

배경은 중앙 기준으로 화면을 덮도록 확대·축소하며 남는 가장자리는 잘라냅니다. 픽셀 크기를 올림 처리하여 미세한 비율 차이로 빈 줄이 생기는 것을 방지합니다.

아이템은 각 맵 첫 방문에 한 번씩 보도 위에 랜덤 배치합니다. 초기 바닥 합계는 3~5개이며 종류별 3~5개가 아닙니다. 소지 무기는 새 스폰 개수에 포함하지 않습니다. 두 종류를 최소 1개씩 포함하고 나머지 종류·수량·위치를 무작위로 정합니다. 초기 아이템은 서로 겹치지 않고 첫 진입 위치를 비워 둡니다. 맵별로 정지·낙하 중 아이템을 저장해 왕복 시 복원하며 재스폰하지 않습니다. 낙하는 현재 맵에서만 진행하고, 다른 맵으로 가면 정지했다가 돌아오면 이어집니다. 획득·교체·버리기에서는 전체 바닥+낙하+소지 총수를 보존합니다. 재실행하면 새 첫 맵으로 시작합니다.

표시된 모든 화살표의 전체 가로 폭·좌우 왕복 범위·추가 여백 16픽셀에 랜덤 아이템이 생성되지 않습니다. 첫 맵은 오른쪽, 두 번째 맵은 양쪽 모두 제외하며 비활성 오른쪽 화살표도 포함합니다. 아이템의 폭과 랜덤 위치 흔들림을 함께 고려해 움직이는 화살표와 가장자리도 겹치지 않도록 배치합니다.

## 게임 리소스

첫 맵 배경은 `newfirststage.png`, 두 번째 맵 배경은 `firstSecondmap.png`입니다. 두 원본은 모두 1672 x 941픽셀이며 같은 비율로 1280 x 720 화면에 맞춥니다. 기존 `firststage.png`는 보존하지만 게임 실행 시에는 사용하지 않습니다.

이동 표시는 `arrow_left_yellow.png`·`arrow_right_yellow.png`를 사용합니다. 원본은 각각 512 x 320픽셀이며 비율을 유지해 80 x 50픽셀로 축소합니다. 하단은 보도 y=140, 기준 바깥 여백은 16픽셀이며 왕복 중에도 최소 10픽셀을 확보합니다. 기존 포털은 로드하거나 표시하지 않습니다. 크기·기준 위치·왕복 폭/주기·스폰 여백·진입 범위·도착 위치는 `settings.py`의 `ARROW_WIDTH`, `ARROW_X`, `ARROW_SWAY_AMPLITUDE`, `ARROW_SWAY_PERIOD`, `ARROW_SPAWN_PADDING`, `ARROW_TRIGGER_HALF_WIDTH`, `STAGE_ENTRY_LEFT_X`, `STAGE_ENTRY_RIGHT_X`에서 조정합니다. 표시 방향은 `STAGE_ARROWS`, 실제 맵은 `STAGE_BACKGROUNDS`로 관리합니다.

체력 HUD는 사용자가 추가한 `HoodMan_HP바_투명배경_pico2d.png` 전체를 원본 비율대로 축소해 그립니다. 원본은 2129 x 404픽셀이며 가로 320픽셀 적용 시 세로는 약 60.72픽셀입니다. 캐릭터 초상화·HP 글자·파란 게이지를 함께 표시하고 원본의 투명 여백을 유지합니다. 기존 `hp_preview_100.png`와 `Heart.png`는 실행 시 로드하거나 표시하지 않습니다. 크기는 `settings.py`의 `HEALTH_BAR_WIDTH`, 위·왼쪽 여백은 `HUD_MARGIN`에서 조정합니다.

아이템은 `dagger_item_pico2d.png`, `steel_pipe_item_pico2d.png`를 수정 없이 바닥·소지·낙하 무기에 재사용합니다. 소지 무기는 새 시트의 40개 오른손 포즈에 손잡이를 맞추고, 평상시에는 단검의 날과 파이프의 긴 부분을 위로 세웁니다. 캐릭터 → 무기 → 추출한 오른손 주먹 순으로 합성해 손잡이를 감싸 쥔 모습을 표시합니다. 전체 순서는 배경 → 해제된 화살표 → 정지한 바닥 무기 → 적 → 캐릭터 → 소지 무기 → 오른손 주먹 → 낙하 무기 → F 안내 → HP 바입니다. `settings.py`의 `WEAPON_HAND_OFFSETS`는 오른손 위치, `WEAPON_GRIPS`는 무기별 손잡이 좌표, `WEAPON_CARRY_ANGLE`·`WEAPON_ATTACK_ANGLES`는 평상시·공격 각도입니다. 크기는 `ITEM_WIDTHS`, 공중 버리기 높이는 `AIR_DROP_HEIGHT`, 획득 범위는 `PICKUP_RADIUS`에서 조정합니다. F 안내는 픽셀 도형으로 그려 외부 폰트가 필요하지 않습니다.

맨손 캐릭터 원본은 `HoodMan_NewSheet_2048x1280.png`이며, IDLE/WALK/RUN/JUMP를 1~4행, 사망을 5행에 매핑합니다. 실행 시에는 정렬한 `assets/character.png`를 사용합니다. 사망 행의 **1~5열은 뒤로 쓰러짐**, **6~8열은 앞으로 엎드림**이며, 각각 프레임 4와 7에서 멈춥니다. 무기 소지와 공격에는 `HoodMan_Weaponless_5States_2048x1280.png` 기반 `assets/armed_character.png`의 IDLE/WALK/RUN/ATTACK/JUMP를 사용하지만 사망하면 소지 여부와 무관하게 새 시트로 전환합니다. 생성된 파일은 저장소에 포함되어 있어 실행 전에 다시 생성할 필요는 없습니다.

맨손 A 공격 중에도 새 시트의 ATTACK 행을 사용하고 끝나면 기존 맨손 시트로 돌아옵니다. 무기 손잡이를 가리는 주먹 전경은 `assets/armed_character_right_hand.png`이며, 아래 `--armed` 명령이 정렬 시트와 함께 재생성합니다. 원본 오른손의 피부 영역과 1픽셀 윤곽만 추출해 다른 손이나 몸 전체가 무기를 가리지 않게 합니다.

다음 명령은 원본 캐릭터 시트에서 파생 파일을 재생성하고 컬러 배경의 검토용 미리보기를 만듭니다. 모듈 실행 방식(`-m`)을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m tools.prepare_character --preview
.\.venv\Scripts\python.exe -m tools.prepare_character --armed --preview
.\.venv\Scripts\python.exe -m tools.prepare_enemy
```

시트는 이미 투명 배경이므로 별도의 색상 기반 배경 제거는 하지 않습니다. 생성 도구는 알파 128 미만의 미세한 잔여 픽셀을 정리하고, 맨손 이동/사망 40개·무기 소지 40개 프레임을 수평 중앙 및 동일한 바닥 기준점에 정렬합니다. 5행 원본의 행 경계를 넘는 점프 머리는 열별 투명 간격으로 분리해 잘리지 않도록 보존합니다. 오른손 전경은 `--armed`에서만 생성합니다. 원본 PNG는 수정하지 않습니다. 점프 높이는 시트 여백이 아닌 게임 물리 좌표로 계산합니다.

적은 새 `hood_man_enemy_pico2d_2048x1024.png`의 8열×4행(대기·이동·공격·쓰러짐) 시트를 사용합니다. 발 기준 정렬한 `assets/enemy.png`를 새 시트로 교체했으며 두 맵 모두 새 적을 표시합니다. 대기는 첫 행을 6 FPS, 추적 이동은 두 번째 행을 8 FPS로 반복하고, 피격 시 네 번째 행을 8 FPS로 1초간 재생한 뒤 마지막 누운 자세를 유지합니다. 위 생성 명령으로 재생성하며 원본은 보존합니다.

## 파일 구성

| --- | --- |
| `main.py` | pico2d 창, 메인 루프, 실행 옵션, 자원 수명 관리 |
| `game.py` | 입력, 이동, 점프, 화살표 왕복·맵 상태 저장·랜덤 스폰, 무기 상호작용 및 낙하·착지 |

## 제약 및 문제 해결

- 이번 버전은 적 인식·추적·근접 공격·플레이어 피해·HP 감소·앞/뒤 사망·적 1회 처치·적/시체 충돌·두 맵 왕복 이동을 지원합니다. 세 번째 맵이 없어 두 번째 맵 오른쪽 화살표는 비활성입니다. 게임 오버 화면/재시작, 다단계 피해량, 실제 카메라, 3단 이상 점프 및 일반 배경 장애물 충돌은 없습니다.
- 배경 사물은 그림이며 캐릭터 이동을 막지 않습니다.
- `Game error`에 파일 경로가 표시되면 해당 이미지가 있는지 확인합니다. 파생 캐릭터 파일이 없으면 위 재생성 명령으로 복구할 수 있습니다.
- 창 생성 또는 SDL 로딩이 실패하면 `requirements.txt`를 가상환경에 설치했는지와 데스크톱 그래픽 환경을 확인합니다. 다른 운영체제의 구동은 검증하지 않았습니다.
- pico2d 1.5.1의 이벤트 및 텍스처 수명 동작에 맞춰 구현했으므로, 의존성 버전을 변경하면 테스트와 실제 창 검증을 다시 실행해야 합니다.
