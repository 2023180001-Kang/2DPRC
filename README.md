# 2DPRC

Python과 pico2d로 구현한 2D 액션 게임의 기본 이동 프로토타입입니다. Shift 달리기, 더블 점프, HP 바 HUD와 랜덤 바닥 무기의 F키 획득·소지·교체를 확인할 수 있습니다. Java 및 JavaScript는 사용하지 않습니다.

## 빠른 실행

현재 작업 공간에는 `.venv`와 의존성이 준비되어 있습니다. 프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe main.py
```

새 환경에서는 먼저 Python 3을 설치한 뒤 다음 명령으로 준비합니다. 검증한 환경은 Windows 및 Python 3.13.15입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

가상환경 활성화나 PowerShell 실행 정책 변경은 필요하지 않습니다. 창이 표시되는 데스크톱 환경이 필요하며, 처음 의존성을 설치할 때는 패키지 다운로드를 위한 네트워크 연결이 필요합니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 지상에서 입력 없음 | 마지막으로 바라본 방향의 IDLE |
| 왼쪽 / 오른쪽 방향키 | 해당 방향으로 걷기 |
| 왼쪽 또는 오른쪽 Shift + 좌우 방향키 | 해당 방향으로 달리기 |
| 이동 중 마지막 Shift 해제 | 걷기로 전환 |
| 방향키 해제 | 즉시 수평 정지 |
| Shift 단독, 좌우 동시 입력 | 수평 정지 |
| 지상에서 스페이스바 새로 누르기 | 한 번 점프 |
| 첫 점프 후 공중에서 스페이스바를 놓고 다시 누르기 | 추가 1회 점프, 한 번의 체공 중 최대 2회 |
| 지상에서 무기 근처로 접근 후 F 새로 누르기 | 가장 가까운 무기 획득, 이미 무기가 있으면 교체 |
| 창 닫기 | 게임 종료 |

좌우 동시 입력에서 한쪽을 놓으면 남은 방향키와 Shift 상태에 따라 다시 이동합니다. Shift와 방향키의 누르는 순서는 관계없습니다. 두 Shift를 함께 눌렀다가 하나만 놓아도 달리기가 유지됩니다. R은 더 이상 달리기 키가 아니며, R+방향키는 걷기입니다. 위아래 방향키와 공격은 지원하지 않습니다.

첫 스페이스바 입력은 지상 점프, 공중의 두 번째 새 입력은 더블 점프입니다. 상승·하강 중 모두 가능하고, 두 번째 도약은 현재 높이에서 수직 속도를 초기 점프 속도로 다시 설정합니다. 기존 속도에 더하지 않습니다. 세 번째 입력은 착지 전까지 무시하고, 착지하면 사용 횟수를 0으로 초기화합니다.

점프 중에도 좌우 및 Shift 조작이 가능하며, 방향키를 놓아도 중력에 따라 하강합니다. 스페이스바를 길게 누르거나 반복 이벤트가 발생해도 자동으로 추가 도약하지 않으며, 사용 횟수를 다 쓴 입력은 예약하지 않습니다. 착지 후에도 새로 눌러야 다음 점프를 시작합니다. 키를 누르는 길이는 도약 속도에 영향을 주지 않습니다.

창 포커스를 잃으면 누른 키와 미처리 점프·획득 요청을 초기화하므로, 돌아온 뒤에는 키를 다시 눌러야 합니다. 이미 시작한 점프·소지 무기·사용한 점프 횟수는 유지하며, 포커스 전환으로 점프 횟수가 회복되지 않습니다.

F로 줍는 범위는 플레이어 발 좌표에서 무기 중심까지 56픽셀입니다. 범위 안에 여러 개가 있으면 가장 가까운 한 개만 선택하며, 길게 누르고 있어도 자동 반복하지 않습니다. 공중·범위 밖에서 누른 F는 나중에 착지하거나 접근해도 자동 실행하지 않으므로 다시 눌러야 합니다.

무기는 한 번에 하나만 들며 처음에는 맨손입니다. 주운 무기는 바닥에서 없어지고 캐릭터 손 근처에 표시됩니다. 이미 무기를 들고 있다면 새 무기로 교체하면서 이전 무기는 발밑에 내려놓습니다. 이동·달리기·점프·착지 중에도 소지하며, 별도의 버리기 키나 공격 기능은 없습니다.

## 적용 설정

| 항목 | 값 |
| --- | --- |
| 화면 | 1280 x 720, 고정 카메라, 비율을 유지하며 배경으로 화면 전체 채우기 |
| 배경 | `newfirststage.png` |
| 걷기 / 달리기 | 180 / 320 화면 픽셀/초 |
| 상태별 애니메이션 | IDLE 6 FPS, WALK 8 FPS, RUN 12 FPS, JUMP 약 7.07 FPS |
| 캐릭터 시트 | `MainCharacter_pico2d_2048x1024.png`, 256 x 256 프레임, 8열 x 4행 |
| 표시 배율 / 지상 발 높이 | 0.6배 / 화면 아래에서 140픽셀, 새 배경의 보도 위 |
| 단일 지상 점프 | 초기 수직 속도 약 678.82 px/s, 중력 1200 px/s², 정점 192픽셀, 체공 약 1.13초 |
| 더블 점프 | 지상 1회+공중 1회, 첫 정점에서 재도약 시 최대 높이 384픽셀, 착지 시 횟수 초기화 |
| 초기 / 최대 체력 | 3 / 3, hp_preview_100.png의 100% HP 바로 표시 |
| 체력 HUD | 우측 상단 PNG 한 장, 가로 320픽셀, 원본 비율 유지, 위·오른쪽 여백 16픽셀 |
| 초기 바닥 아이템 | 실행당 합계 3~5개, 단검·쇠파이프 최소 1개씩 포함 |
| 아이템 크기 | 단검 가로 44픽셀, 쇠파이프 가로 64픽셀, 원본 비율 유지 |
| 무기 획득 | 지상 F, 중심 거리 56픽셀 이내, 소지 1개 및 교체 시 이전 무기 드롭 |
| 초기 위치 / 시선 | 화면 수평 중앙 / 오른쪽 |
| 화면 경계 | 전체 프레임이 화면에 머물도록 제한, 경계에서도 상태 애니메이션 유지 |
| 렌더링 목표 | 최대 60 FPS, 환경에 따라 실제 값은 낮아질 수 있음 |

설정은 `settings.py`에서 조정합니다. 화면 크기, 캐릭터 배율, 바닥 높이를 변경하면 배경과 캐릭터 배치를 다시 확인해야 합니다.

단일 점프의 높이와 속도는 이전 버전 그대로입니다. 더블 점프의 전체 높이·체공 시간은 두 번째 입력 시점에 따라 달라집니다. 네 번째 행의 8프레임을 각 도약에서 재사용하며, 두 번째 도약 때 애니메이션을 다시 시작합니다. 좌우/Shift 변경이나 세 번째 입력으로는 프레임을 초기화하지 않습니다. 착지하면 현재 입력에 맞는 지상 상태로 돌아옵니다.

체력 HUD는 `hp_preview_100.png` 한 장을 표시하며 이동·점프 중에도 화면 우측 상단에 고정됩니다. 기존 하트 3개 표시는 제거했습니다. 현재 버전에는 피해·회복·사망 기능이 없으므로 제공된 100% HP 이미지를 표시하며, 체력 변화에 따른 게이지 가변 표시는 구현하지 않습니다.

배경은 중앙 기준으로 화면을 덮도록 확대·축소하며 남는 가장자리는 잘라냅니다. 픽셀 크기를 올림 처리하여 미세한 비율 차이로 빈 줄이 생기는 것을 방지합니다.

아이템은 게임 시작 시 한 번만 보도 위에 랜덤 배치합니다. 초기 합계는 3~5개이며 종류별 3~5개가 아닙니다. 두 종류를 최소 1개씩 포함하고 나머지 종류·수량·위치를 무작위로 정합니다. 초기 아이템은 서로 겹치지 않고 캐릭터 시작 위치를 비워 둡니다. 획득·교체 입력이 없으면 바닥의 개수와 위치를 유지합니다. 획득 후에는 바닥 개수가 줄고 교체 시에는 기존 무기가 발밑으로 돌아가며, 바닥+소지 총수는 보존합니다. 재실행하면 다시 초기 스폰합니다.

## 개발 및 검증

이미지 생성 도구와 테스트에는 Pillow가 추가로 필요합니다. 게임 실행 자체는 `requirements.txt`만으로 가능합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe main.py --frames 180
.\.venv\Scripts\python.exe -m tools.verify_runtime
```

- 자동 테스트는 129개이며 더블 점프 횟수·속도·높이·착지·포커스·애니메이션, 기존 무기·아이템·입력·화면 경계를 검증합니다.
- `--frames N`은 양의 정수 N프레임 후 종료하고 실제 실행 시간 및 평균 FPS를 출력합니다.
- `tools.verify_runtime`은 실제 창에서 이동·단일/더블 점프·초기 스폰·F 획득 및 교체 시나리오를 실행하고 화면 37개 및 측정 결과를 `artifacts/`에 생성합니다. 이미지 누락 시 실제 로딩 실패와 자원 정리도 검증합니다. 실행 중에는 게임 창을 조작하지 마세요.
- 실제 창 입력 검증은 물리 키보드의 사람 조작이 아닌 이벤트 큐 기반 검증입니다. 상세 결과와 남은 확인 사항은 `VERIFICATION.md`를 참조합니다.

## 게임 리소스

현재 배경은 사용자가 추가한 `newfirststage.png`입니다. 기존 `firststage.png`는 보존하지만 게임 실행 시에는 사용하지 않습니다.

체력 HUD는 사용자가 추가한 `hp_preview_100.png` 전체를 원본 비율대로 축소해 그립니다. 아이콘과 게이지를 함께 표시하고 원본의 투명 여백은 유지합니다. 기존 `Heart.png`는 실행 시 로드하거나 표시하지 않습니다. 크기는 `settings.py`의 `HEALTH_BAR_WIDTH`에서 조정합니다.

아이템은 `dagger_item_pico2d.png`, `steel_pipe_item_pico2d.png`를 수정 없이 바닥·소지 무기 표시에 재사용합니다. 원본 비율을 유지해 축소하며, 캐릭터의 32개 포즈에서 실제 보이는 영역보다 작은지 테스트합니다. 순서는 배경 → 바닥 무기 → 캐릭터 → 소지 무기 → HUD입니다. 크기는 `settings.py`의 `ITEM_WIDTHS`, 획득 범위는 `PICKUP_RADIUS`, 손 기준점은 `WEAPON_HAND_OFFSETS`에서 조정합니다. 별도 무장 캐릭터 시트나 새 텍스처를 추가하지 않습니다.

현재 캐릭터 원본은 `MainCharacter_pico2d_2048x1024.png`이며, IDLE/WALK/RUN/JUMP를 위에서부터 1~4행에 매핑합니다. 실행 시에는 새 원본을 정렬한 `assets/character.png`를 사용합니다. 생성된 파일은 저장소에 포함되어 있어 실행 전에 다시 생성할 필요는 없습니다. 기존 `MainCharacter.png`는 보존만 하며 게임과 생성 도구에서 읽지 않습니다.

다음 명령은 원본 캐릭터 시트에서 파생 파일을 재생성하고 컬러 배경의 검토용 미리보기를 만듭니다. 모듈 실행 방식(`-m`)을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m tools.prepare_character --preview
```

새 시트는 이미 투명 배경이므로 별도의 색상 기반 배경 제거는 하지 않습니다. 생성 도구는 알파 128 미만의 미세한 잔여 픽셀을 정리하고, 32개 프레임을 수평 중앙 및 동일한 발 기준점에 정렬합니다. 원본 PNG는 수정하지 않습니다. 점프 높이는 시트 여백이 아닌 게임 물리 좌표로 계산합니다.

## 파일 구성

| 경로 | 역할 |
| --- | --- |
| `main.py` | pico2d 창, 메인 루프, 실행 옵션, 자원 수명 관리 |
| `game.py` | 입력, 이동, 점프, 랜덤 스폰, 무기 획득·교체 및 상태 |

| `rendering.py` | 배경, 바닥·소지 무기, 캐릭터 및 체력 HUD 렌더링 |
| `resources.py` | 소스 위치 기준 이미지 경로, 오류 안내, 텍스처 해제 |
| `settings.py` | 크기, 속도, 애니메이션 및 배치 설정 |

| `DEVELOPMENT.md` | 개발 기준과 20단계 진행 기록 |
| `VERIFICATION.md` | 측정 결과, 인수 기준별 검증, 남은 제약 |
| `PRD.md` | 개발 요구 사항 |

## 제약 및 문제 해결

- 이번 버전은 고정 화면의 이동·더블 점프 프로토타입입니다. 실제 횡스크롤 카메라, 전투, 3단 이상 점프, 플랫폼 및 장애물 충돌은 없습니다.
- 배경 사물은 그림이며 캐릭터 이동을 막지 않습니다.
- `Game error`에 파일 경로가 표시되면 해당 이미지가 있는지 확인합니다. 파생 캐릭터 파일이 없으면 위 재생성 명령으로 복구할 수 있습니다.
- 창 생성 또는 SDL 로딩이 실패하면 `requirements.txt`를 가상환경에 설치했는지와 데스크톱 그래픽 환경을 확인합니다. 다른 운영체제의 구동은 검증하지 않았습니다.
- pico2d 1.5.1의 이벤트 및 텍스처 수명 동작에 맞춰 구현했으므로, 의존성 버전을 변경하면 테스트와 실제 창 검증을 다시 실행해야 합니다.
